# Common Java 8 → Java 25 Build Errors

| Symptom | Likely cause | Fix |
|---|---|---|
| `package javax.xml.bind does not exist` (JAXB) or similar for JAX-WS/CORBA | Java EE module removed in JDK 11, no longer on the bootclasspath | Add the equivalent standalone dependency (e.g. `jakarta.xml.bind:jakarta.xml.bind-api` + a runtime impl), or replace the usage |
| `error: invalid source release: 11` (or 17/21/25) at Stage N | `maven-compiler-plugin`/Gradle toolchain predates the stage's target JDK | Bump the compiler plugin/toolchain version for this stage before retrying |
| `package javax.persistence does not exist` (or servlet/validation/annotation) | Framework was bumped to Jakarta EE 9+ but an import was missed | Change `javax.*` import to the matching `jakarta.*` import |
| `cannot find symbol` on a getter/setter after converting a class to a record | Callers still use `getX()`/`setX()` bean-style accessors | Update call sites to the record's accessor method (`x()`), or keep a compatibility method if the class is a public API boundary |
| `error: switch expression does not cover all possible input values` | Sealed type added a new permitted subtype without a corresponding `case` | Add the missing `case` branch |
| `error: incompatible types` after replacing `Date`/`Calendar` with `java.time.*` | Call site still expects the old type | Update the call site's parameter/return type, or add an explicit conversion at the boundary |
| `cannot find symbol: method getFirst()/getLast()` | Called on a collection type/interface that doesn't implement `SequencedCollection` | Confirm the runtime type is a supported collection (e.g. `ArrayList`, `LinkedHashMap`), or fall back to `get(0)`/`get(size()-1)` for that type |
| Maven `Fatal error compiling: invalid target release: 25` | `maven-compiler-plugin` version predates JDK 25 support, or wrong `release`/`source`/`target` value | Bump `maven-compiler-plugin` to a current version; set `<release>25</release>` |
| `NoClassDefFoundError` / `ClassNotFoundException` for a Jakarta/Spring class at compile or test time | Old `javax.*`-based dependency still on the classpath alongside a `jakarta.*`-based one | Remove the stale `javax.*` dependency and its exclusions in `pom.xml`/`build.gradle` |
| Lombok-generated methods missing after adding a newer JDK | Lombok version too old for the target JDK | Bump Lombok to a version that supports the target JDK (1.18.34+ for very recent JDKs) |
| JUnit 4 test fails to run / not discovered | Test still uses `org.junit.Test` under a JUnit 5 runner | Migrate the test class to JUnit Jupiter (`org.junit.jupiter.api.Test`) if the JUnit upgrade was requested; otherwise add `junit-vintage-engine` (test scope) and report the class as deprecated JUnit 4 |
| JUnit 3 test (`extends TestCase`) silently not run | The JUnit Platform only runs JUnit 3/4 through the Vintage engine | Same as above — Jupiter migration if requested, otherwise `junit:junit` 4.13.2 + `junit-vintage-engine`, reported as deprecated JUnit 3 |
| Deprecation warnings for `SpringRunner` / `SpringJUnit4ClassRunner` or the Vintage engine on Spring Boot 4 | Spring Framework 7 deprecates its JUnit 4 support; JUnit 6 deprecates `junit-vintage-engine` | Not a build error — do not suppress or downgrade. List the affected test classes as deprecated JUnit 4 in the summary |

## Legacy Java 8-era stacks

These rarely surface as a tidy compiler error — they fail while generating or
parsing bytecode. Fix them by removing or replacing the library, never by adding
`--add-opens`.

| Symptom | Likely cause | Fix |
|---|---|---|
| `IllegalArgumentException: Unsupported class file major version NN`, or `ArrayIndexOutOfBoundsException` during component scan / context startup | Spring 3.x/4.x, Hibernate 3/4, cglib or javassist bundling an ASM that cannot read the target JDK's class files | Bump Spring to 5.3.x (`javax`) / Hibernate to 5.6.x, and delete explicit `cglib`, `cglib-nodep` and `javassist` dependencies — Spring 5+ repackages cglib and Hibernate 5.3+ uses ByteBuddy |
| `InaccessibleObjectException: Unable to make ... accessible: module java.base does not "opens java.lang"` | An old proxy/bytecode library reflecting into the JDK under JDK 17+ strong encapsulation | Remove the stale library (usually cglib/javassist) or bump it. Adding `--add-opens` hides the problem and is not the fix |
| `package org.springframework.orm.hibernate3 does not exist` | `hibernate3` (and `hibernate4`) support was removed in Spring 5 | Rewrite the imports onto `org.springframework.orm.hibernate5` (`LocalSessionFactoryBean`, `HibernateTransactionManager`, `HibernateTemplate`), in step with the Hibernate 5.x bump |
| `AuditInterceptor is not abstract and does not override abstract method onSave(...)` / `cannot find symbol: class Type` after a Hibernate bump | The `org.hibernate.Interceptor` SPI signatures and `org.hibernate.type.Type` changed across 4 → 5 → 6 | Prefer replacing the interceptor with `PreInsertEventListener` / `PreUpdateEventListener` registered via an `Integrator`, rather than chasing the new signatures |
| `ClassNotFoundException: org.hibernate.dialect.Oracle10gDialect` | Versioned Oracle dialects were removed in Hibernate 6 | Delete the `hibernate.dialect` property — Hibernate auto-detects the dialect from the JDBC connection |
| `package org.codehaus.jackson... does not exist`, or `cannot find symbol: JsonMethod` / `SerializationConfig.Feature` | Jackson 1 code compiled against a Jackson 2 dependency | Rewrite to `com.fasterxml.jackson.*`: `SerializationFeature`/`DeserializationFeature`/`MapperFeature`, `PropertyAccessor` instead of `JsonMethod`, `MappingJackson2HttpMessageConverter`. Rewrite the whole converter bean — the enums have no 1:1 replacement |
| `cannot find symbol: method getKeys()` / `getQuiet()` / `class Element` on a cache | Ehcache 2 API used against Ehcache 3 | Ehcache 3's `Cache` is `Iterable<Cache.Entry<K,V>>` with no key listing and no statistics-free read: iterate for keys, use `get(key)` (returning the value directly). Flag the behavioural change |
| `package org.springframework.cache.ehcache does not exist` / `cannot find symbol: class EhCacheCacheManager` | Spring 6 removed its Ehcache 2 cache support | `org.springframework.cache.jcache.JCacheCacheManager` over Ehcache 3's JSR-107 provider, with `javax.cache:cache-api`. `javax.cache` is JSR-107 — never rename it to `jakarta.cache` |
| `ClassNotFoundException: org.hibernate.cache.ehcache.EhCacheRegionFactory`, or a `RegionFactory` strategy named `ehcache` that cannot be resolved | `hibernate-ehcache` was removed in Hibernate 6 | Replace with `hibernate-jcache`; set `hibernate.cache.region.factory_class=jcache` and `hibernate.javax.cache.provider=org.ehcache.jsr107.EhcacheCachingProvider` |
| JAXB `ClassNotFoundException` / `NoClassDefFoundError` while Ehcache 3 parses `ehcache.xml` | Ehcache 3 variant does not match the namespace on the classpath | `javax.xml.bind` 2.3 dependencies before the Spring Boot 3.x stage; the `jakarta` classifier of `org.ehcache:ehcache` from that stage on |
| `NoSuchMethodError` / `NoClassDefFoundError` inside `com.fasterxml.jackson.*` at the first (de)serialization | Jackson modules at a different version than `jackson-databind` | Import `com.fasterxml.jackson:jackson-bom` (or let the Spring Boot BOM manage Jackson) and delete per-artifact versions |
| `InaccessibleObjectException` from `com.fasterxml.jackson.module.afterburner` | Afterburner's bytecode generation under JDK 17 strong encapsulation | Replace with `jackson-module-blackbird`, or remove the module |
| `package com.fasterxml.jackson.databind does not exist` on the Spring Boot 4.x stage | Jackson 3 moved `databind` and `core` to `tools.jackson.*` | Imports → `tools.jackson.databind.*` / `tools.jackson.core.*`; keep `com.fasterxml.jackson.annotation.*` unchanged. Never re-add Jackson 2 databind |
| `exception JsonProcessingException is never thrown`, or `cannot find symbol` for `configure(...)` / `registerModule(...)` on an `ObjectMapper` under Jackson 3 | Jackson 3 exceptions are unchecked (`JacksonException`) and mappers are immutable | Build the mapper with `JsonMapper.builder()…build()`; catch `JacksonException` where the code caught `JsonProcessingException` |
| `package org.apache.log4j does not exist` | log4j 1.2 removed in favour of SLF4J/Logback | `org.slf4j.Logger` + `LoggerFactory.getLogger(X.class)`; convert `"a=" + a` concatenation to `"a={}"` parameters |
| `StackOverflowError` on the first log statement | `log4j-over-slf4j` and `log4j:log4j` both on the classpath, routing into each other | Remove the real `log4j:log4j` dependency |
| Duplicate/ambiguous `com.google.common.collect.*` classes | `google-collections` and `guava` both present (same packages) | Remove `com.google.collections:google-collections` (and `<exclusion>` it wherever it arrives transitively); keep the newest Guava |
| `cannot find symbol: method toStringHelper` / `firstNonNull` on `com.google.common.base.Objects` | Removed from newer Guava | `MoreObjects.toStringHelper` / `MoreObjects.firstNonNull` |
| `Stopwatch() has private access`, `cannot find symbol: method elapsedMillis()` | Guava's public `Stopwatch` constructor and `elapsedMillis` were removed | `Stopwatch.createStarted()` / `createUnstarted()`; `elapsed(TimeUnit.MILLISECONDS)` |
| `cannot find symbol: method makeComputingMap` / `expiration` on `MapMaker` | Computing maps were removed from Guava | `CacheBuilder.newBuilder()…build(CacheLoader)` (`LoadingCache`) |
| `cannot find symbol: method sameThreadExecutor()`, or no suitable method for `Futures.transform(future, fn)` / `Futures.addCallback(future, cb)` | Removed from newer Guava; the executor argument is now mandatory | `MoreExecutors.directExecutor()`, passed explicitly |
| `cannot find symbol: method closeQuietly(Closeable)` / `class InputSupplier` | Removed from Guava's I/O utilities | try-with-resources; `ByteSource` / `CharSource` |
| `NoSuchMethodError` inside `com.google.common.*` at runtime | Two Guava versions on the classpath (one transitive), resolved to the older | Pin one version via `com.google.guava:guava-bom` in `<dependencyManagement>` |
| `cannot find symbol: class MockHttpServletRequest` / `DelegatingServletOutputStream` in production code | `spring-mock` (a test library) was used at runtime scope and has been removed | Implement real `HttpServletRequestWrapper` / `HttpServletResponseWrapper` and a `ServletOutputStream` subclass (Servlet 3.1+ requires `isReady()`/`setWriteListener()`) |
| `cannot find symbol: class Mockito` / mock creation fails with a cglib error | Mockito 1.x on JDK 9+, or `mockito-all` removed in favour of `mockito-core` | Use `mockito-core` (4.11.0 while the release level is 8, 5.x from the Java 17 stage); add `mockito-inline` only if final classes/statics are mocked on 4.x |
| Surefire/Failsafe fails before any test runs (`The forked VM terminated without properly saying goodbye`) | Plugin 2.x forking a JVM on JDK 9+ | Bump both plugins to 3.2.5+ |
